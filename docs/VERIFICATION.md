# Verification

What is machine-checked, with which tool, under which bounds, and what is not.

## Scope

The policy rules of the mandate program live in `programs/mandate/src/logic/` as pure functions over plain data (no Anchor types). The proof crate `programs/mandate/proofs` compiles that same source with `#[path]`, so the proofs cover exactly the code that ships in the program. Account validation, PDA derivation, signer checks and the token CPI are in the Anchor layer and are covered by the 36 LiteSVM tests, not by the proofs.

## Kani results

Tool: Kani 0.68.0 (CBMC with CaDiCaL), run on Apple Silicon, `cargo kani --harness <name>` from `programs/mandate/proofs`. Command for all harnesses: `tools/run-proofs.sh`. Run on 2026-11-24; all ten harnesses report `VERIFICATION:- SUCCESSFUL`.

| Harness | Property | Time |
|---|---|---|
| `spend_never_exceeds_cap` | For any well-formed state (`spent <= cap`) and any request and time, an authorised spend leaves `spent <= cap` and increments the nonce by one | 22 s |
| `revoked_mandate_authorizes_nothing` | A revoked mandate rejects every spend, every limit update and every agent rotation, for all inputs | 5 s |
| `expired_mandate_authorizes_nothing` | When `now >= expiry` no spend is authorised | 10 s |
| `spend_logic_never_panics_for_any_input` | `authorize_spend` and `roll_period` never panic or overflow for any state in the type domain | 18 s |
| `management_logic_never_panics_for_any_input` | `authorize_revoke`, `authorize_limit_update`, `authorize_agent_rotation` never panic or overflow for any input | 11 s |
| `period_rollover_never_resets_spend_inside_the_same_period` | If `now < period_start + period_seconds`, spend and window start are unchanged | 8 s |
| `period_rollover_window_contains_now_after_roll` | After a roll, `period_start <= now < period_start + period_seconds` | 37 s |
| `authorized_spend_requires_every_allowlist` | An authorised spend implies program, payee and tool are on their allowlists, the signer is the agent, and the mandate is not revoked | 26 s |

## Bounds and assumptions, stated honestly

- Loop unwinding is 34: allowlists have at most 8 entries and each key comparison is a 32-byte loop. Harnesses fail if the bound is too small, so a passing run means the bound was sufficient for the code as written.
- Allowlist lengths are at most their capacities (4 programs, 4 payees, 8 tools), which the program enforces at creation and update.
- "Well-formed state" means `spent_in_period <= period_cap`, `60 <= period_seconds <= 31,536,000`, and `0 <= period_start < 2^33`. The program establishes the first two at creation and update; the third bound is a modelling limit (2^33 seconds is the year 2242).
- Timestamps in the rollover, sequence and cap harnesses are bounded to `[0, 2^33)`. The two no-panic harnesses use the full domain of every field.
- The sequence harness checks length three, not arbitrary length. The inductive step is covered by `spend_never_exceeds_cap`: any well-formed state stays well-formed after an authorised spend, and `authorize_limit_update` rejects a cap below the spent amount.
- The proofs say nothing about the token program, the Solana runtime, account substitution, or the dapp layer.

## Test evidence

- `cargo test -p selvedge-mandate`: 36 program tests (positive and negative paths: cap boundary, rollover, revoked, expired, allowlists, wrong signer, owner-only updates, overflow, replay, closed account reuse, token delegation limits) against the built SBF binary in LiteSVM.
- Conformance vectors: 289 policy cases generated by the Rust logic (`programs/mandate/proofs/examples/generate_policy_vectors.rs`) are executed by the TypeScript engine (`packages/engine/tests/policyVectors.test.ts`).

## Certora Solana Prover

Attempted on 2026-11-24. Outcome: **the build and rule specification work; the prover run did not happen because it needs a Certora account key.**

- `cargo-certora-sbf` 0.3.5 installed and `cargo certora-sbf --manifest-path programs/mandate/certora/Cargo.toml` built `selvedge_mandate_certora.so` against the same `src/logic` source, with `cvlr` 0.6.3.
- The rule `revoked_mandate_never_authorizes_a_spend` (nondeterministic state and request, revoked set, `authorize_spend` must return an error) is written in `programs/mandate/certora/src/rules.rs`; the configuration is `programs/mandate/certora/rules.conf`.
- `certoraSolanaProver rules.conf` (certora-cli 8.20.3) stops with: `The environment variable CERTORAKEY does not contain a Certora key. To get a free Certora key please visit https://www.certora.com/signup`. Creating that account is an owner action; no property is claimed as proved by Certora.
- To run it once a key exists: `export CERTORAKEY=...; cd programs/mandate/certora && cargo certora-sbf && certoraSolanaProver rules.conf`.
